# البناء التلقائي والمزامنة السحابية

## GitHub Actions لبناء APK

أضيف سير العمل `.github/workflows/android-apk.yml`. يعمل تلقائيًا عند كل `push` إلى الفرع `main`، ويمكن تشغيله يدويًا من تبويب **Actions** عبر **Run workflow**.

ينفذ سير العمل تثبيت الاعتماديات، إعداد Java وAndroid SDK، إنشاء مشروع Android من Expo، وبناء نسخة Release من APK. بعد النجاح يحفظ APK كـ **Artifact** لمدة 30 يومًا، ويحدّث إصدارًا تجريبيًا باسم `latest-apk` داخل GitHub Releases.

للتنزيل: افتح المستودع ثم **Actions** لاختيار التشغيل وملف Artifact، أو افتح **Releases** لتنزيل `app-release.apk`. لا يحتاج هذا المسار إلى `EXPO_TOKEN` لأنه يبني المشروع على خوادم GitHub بدل خدمة EAS.

## النسخ الاحتياطي السحابي

أضيفت طبقة مزامنة اختيارية مرتبطة بحساب المستخدم وقاعدة بيانات المشروع. يحافظ التطبيق على التخزين المحلي ويعمل دون إنترنت، ثم يرفع نسخة JSON تلقائيًا بعد تغييرات البيانات عندما يتوفر الاتصال والمصادقة. كما توجد في الإعدادات أزرار **حفظ سحابي الآن** و**استعادة سحابية**.

الاستعادة تعرض نافذة تأكيد قبل استبدال البيانات المحلية. أما الاستيراد والتصدير المحلي بصيغة JSON فباقٍ كما هو. تستخدم المزامنة اتصال HTTPS ومسارات API محمية بالمصادقة، وتخزن نسخة منفصلة لكل حساب مستخدم.

هذه النسخة تستخدم قاعدة بيانات المشروع كخدمة سحابية مدمجة، وليست ربطًا مباشرًا بـ Firebase أو Google Drive. لإضافة Google Drive لاحقًا يلزم تفعيل موصل OAuth ونطاقات Drive المناسبة، مع تحديد سياسة تعارض واضحة بين الأجهزة.

## ملاحظات تشغيلية

يجب تسجيل الدخول داخل التطبيق حتى تعمل المزامنة السحابية. إذا لم يكن المستخدم مسجلًا أو لم يتوفر الإنترنت، يفشل الرفع بصمت أثناء النسخ التلقائي ولا تتأثر البيانات المحلية. يوصى بإضافة تشفير طرفي قبل تخزين البيانات السحابية إذا كانت البيانات تحتوي معلومات مدرسية حساسة.
